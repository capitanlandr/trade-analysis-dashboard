# Deployment Guide

## Prerequisites

- GitHub account with repository access
- Vercel account (free tier works)
- Python 3.9+ for local pipeline development
- Google Drive folder with Commish Tiers documents (optional, for Archive feature)

## Architecture Overview

This is a **static site deployment**:
- **Frontend**: React SPA built with Vite, hosted on Vercel
- **Data**: Static JSON files generated by Python pipeline, committed to repo
- **No backend server** - all data is pre-generated and served as static files

## Initial Setup

### 1. Configure Google Drive Folder (Optional)

Only needed if you want the Commish Tiers Archive feature:

1. Create or identify your Google Drive folder containing Commish Tiers documents
2. Set folder sharing to "Anyone with the link can view"
3. Copy the folder ID from the URL:
   ```
   https://drive.google.com/drive/folders/[FOLDER_ID]
   ```

### 2. Configure Environment Variables

**Local Development:**

Create `dashboard/frontend/.env`:
```env
VITE_DRIVE_FOLDER_ID=your_folder_id_here
```

**Vercel Production:**

1. Go to your Vercel project dashboard
2. Navigate to Settings → Environment Variables
3. Add (only if using Archive feature):
   - `VITE_DRIVE_FOLDER_ID` = your folder ID

Note: The folder ID is not sensitive since it's visible in the iframe URL. You can commit it to `.env` if preferred.

### 3. Deploy to Vercel

**Option A: Automatic (Recommended)**

1. Push your code to GitHub:
   ```bash
   git add .
   git commit -m "feat: add commish tiers archive"
   git push origin main
   ```

2. Vercel automatically detects the push and deploys

**Option B: Manual Deploy**

1. Install Vercel CLI:
   ```bash
   npm install -g vercel
   ```

2. Deploy:
   ```bash
   cd trade-analysis-dashboard-clean
   vercel --prod
   ```

## Updating Data

### Pipeline Execution

The dashboard displays static JSON data generated by the Python pipeline. To update the data:

**Method 1: Automated (Recommended)**
- GitHub Actions runs `update_dashboard.py` daily at 9 AM EST
- Manual trigger: Actions tab → "Update Dashboard Data" → "Run workflow"

**Method 2: Local Execution**
```bash
python3 update_dashboard.py
```

The pipeline workflow:
1. Detects current week from Sleeper API
2. Fetches latest trades, standings, and waiver data
3. Runs playoff simulations (10,000 Monte Carlo scenarios)
4. Calculates progressive draft order projections
5. Analyzes waiver wire efficiency metrics
6. Generates 7 dashboard JSON files (api-trades.json, api-standings.json, etc.)
7. Commits and pushes to GitHub
8. Triggers Vercel auto-deployment

**Generated Files:**
- `dashboard/frontend/public/api-trades.json` - Trade analysis
- `dashboard/frontend/public/api-teams.json` - Manager rankings
- `dashboard/frontend/public/api-stats-summary.json` - League stats
- `dashboard/frontend/public/api-standings.json` - Current week standings
- `dashboard/frontend/public/api-playoff-scenarios.json` - Playoff probabilities
- `dashboard/frontend/public/waiver-wire-page.json` - Waiver wire metrics
- `dashboard/frontend/public/api-draft-order.json` - Draft order projections

## Verifying Deployment

1. **Check Vercel Dashboard**
   - Verify deployment status is "Ready"
   - Check build logs for errors
   - Confirm build time is reasonable (~2-3 minutes)

2. **Test All Dashboard Pages**
   - Navigate to your Vercel URL
   - **Overview**: Verify trade analysis and manager rankings display
   - **Standings**: Check current week standings load correctly
   - **Playoff Scenarios**: Confirm simulation results display
   - **Draft Order**: Verify progressive projections render
   - **Waiver Wire**: Check all 4 metrics cards display
   - **Archive**: Confirm Google Drive folder embeds (if configured)

3. **Verify Data Freshness**
   - Check timestamps on JSON files in repo
   - Verify data matches current Sleeper league state
   - Confirm current week is correct in standings

4. **Check Browser Console**
   - Open browser DevTools (F12)
   - Look for any errors in Console tab
   - Verify JSON files load successfully (Network tab)
   - Check for 404 errors on data files

## Troubleshooting

### Google Drive Embed Not Loading

**Symptoms**: Blank iframe or error message

**Solutions**:
1. Verify `VITE_DRIVE_FOLDER_ID` is set correctly
2. Check folder sharing settings (must be "Anyone with the link")
3. Test folder URL directly: `https://drive.google.com/drive/folders/[FOLDER_ID]`
4. Clear browser cache and reload

### Environment Variables Not Applied

**Symptoms**: Features using env vars don't work

**Solutions**:
1. Verify variables are set in Vercel dashboard
2. Redeploy after adding/changing variables
3. Check variable names match exactly (case-sensitive)
4. For local dev, restart dev server after changing `.env`

### Build Failures

**Symptoms**: Vercel deployment fails

**Solutions**:
1. Check build logs in Vercel dashboard
2. Verify all dependencies are in `package.json`
3. Test build locally: `npm run build`
4. Check for TypeScript errors: `npm run lint`

### Data Not Updating

**Symptoms**: Dashboard shows old data

**Solutions**:
1. Check GitHub Actions run history
2. Verify JSON files were committed
3. Manually trigger workflow from Actions tab
4. Check Vercel deployment triggered after commit

## Rollback

If a deployment has issues:

1. **Via Vercel Dashboard**
   - Go to Deployments
   - Find previous working deployment
   - Click "..." → "Promote to Production"

2. **Via Git**
   ```bash
   git revert HEAD
   git push origin main
   ```

## Monitoring

## Security Notes

- Google Drive folder ID is public (visible in iframe)
- No sensitive data in environment variables
- All API calls are client-side (no secrets exposed)
- Folder permissions controlled by Google Drive settings
