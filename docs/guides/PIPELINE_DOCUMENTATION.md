# Pipeline Documentation

## Overview

The Trade Analysis Dashboard pipeline consists of **12 stages** that fetch, analyze, and deploy fantasy football data. Each stage has a specific purpose and dependencies, orchestrated by `update_dashboard.py` to ensure correct execution order.

## Stage 0: Week Detection 🔍

**Script:** `pipeline/scripts/detect_current_week.py`  
**Purpose:** Validate current week using roster records to avoid Tuesday timing bugs  
**Dependencies:** None (runs first)  
**Output:** `pipeline/config/current_week.json`

### Why Stage 0 Exists

Sleeper's `leg` field advances to the next week during Tuesday waiver processing (~3 AM EST), but games haven't been played yet. Without validation, scripts would incorrectly think the new week is complete.

### How It Works

1. **Fetch league info** from Sleeper API
2. **Fetch all rosters** with win/loss/tie records
3. **Calculate weeks completed** using formula: `(wins + losses + ties) / 2`
4. **Validate consistency** across all teams
5. **Compare to Sleeper's leg** for sanity check
6. **Write validated week** to config file

### Formula (Dual-Game Format)

```python
weeks_completed = (wins + losses + ties) / 2

# Example: Team with 6-6-0 record
# = (6 + 6 + 0) / 2 = 12 games / 2 = Week 6 complete
```

### Output Format

```json
{
  "current_week": 12,
  "last_updated": "Generated by detect_current_week.py"
}
```

### Scripts That Depend on This Stage

- **Stage 8** (`fetch_standings.py`) - Week context
- **Stage 9** (`simulate_playoff_scenarios.py`) - Remaining games calculation ⚠️ Critical
- **Stage 9** (`calculate_playoff_scenarios.py`) - Clinch scenarios
- **Dashboard** - Week labels and context

### Tuesday Timing Example

```
Monday Night (11:30 PM): Week 12 games complete
├─ Rosters: 6-6-0 (12 games / 2 = Week 6) ✓
└─ Sleeper leg: 12 ✓

Tuesday Morning (3 AM): Waivers process
├─ Rosters: Still 6-6-0 (Week 6) ✓
└─ Sleeper leg: 13 (advanced!) ⚠️

Stage 0 Detection:
├─ Calculates: 12 games / 2 = Week 6
├─ Compares: Week 6 vs leg 13 (mismatch)
└─ Returns: Week 6 ✓ (uses roster records as truth)
```

For detailed information, see [WEEK_DETECTION.md](./WEEK_DETECTION.md).

## Stages 1-4: Trade Analysis Pipeline

### Stage 1: Fetch Trades 📥

**Script:** `pipeline/stage1_fetch_trades.py`  
**Purpose:** Fetch all trades from Sleeper API  
**Dependencies:** None  
**Output:** Raw trade data

**What it does:**
- Queries Sleeper API for all league trades
- Filters for accepted trades (status = "complete")
- Extracts transaction details and participants
- Writes raw data for Stage 2 processing

---

### Stage 2: Extract Assets 📦

**Script:** `pipeline/stage2_extract_assets.py`  
**Purpose:** Parse trades into players and draft picks  
**Dependencies:** Stage 1 output  
**Output:** Structured asset lists

**What it does:**
- Parses raw trade data
- Identifies player IDs and draft pick references
- Maps team involvement (who traded what)
- Structures data for value assignment

---

### Stage 3: Cache Dynasty Values 💰

**Script:** `pipeline/stage3_cache_values.py`  
**Purpose:** Fetch current dynasty values from KeepTradeCut  
**Dependencies:** Stage 2 output  
**Output:** `dynasty_values_cache.json`

**What it does:**
- Queries KeepTradeCut API for player values
- Caches values locally to avoid repeated API calls
- Updates stale values (>24 hours old)
- Maps Sleeper player IDs to dynasty values

**API Rate Limits:**
- Respects KeepTradeCut rate limits
- Uses exponential backoff on errors
- Caches aggressively to minimize requests

---

### Stage 4: Generate Trade Analysis 📊

**Script:** `pipeline/stage4_final.py`  
**Purpose:** Complete trade analysis with value calculations  
**Dependencies:** Stages 1-3 outputs  
**Output:** `league_trades_analysis_pipeline.csv`

**What it does:**
- Combines asset data with dynasty values
- Calculates trade values for each side
- Determines winners/losers
- Generates analysis metrics
- Writes final CSV for dashboard consumption

**Output Columns:**
- Trade date, participants
- Assets traded (players/picks)
- Dynasty values for each asset
- Total value each side
- Value differential
- Winner/loser determination

## Stages 7-10: Dashboard Generation

### Stage 7: Convert CSVs to JSON 📄

**Script:** `pipeline/scripts/generate_dashboard_json.py`  
**Purpose:** Transform CSV data into dashboard-consumable JSON  
**Dependencies:** Stages 4, 5 outputs  
**Output:** 
- `dashboard/frontend/public/api-trades.json`
- `dashboard/frontend/public/api-teams.json`
- `dashboard/frontend/public/api-stats-summary.json`

**What it does:**
- Reads trade analysis CSV
- Reads team identity mapping CSV
- Converts to JSON format
- Calculates summary statistics
- Writes to dashboard public directory

**Important:** This stage does NOT handle standings or playoff data (those are written directly by their respective stages).

---

### Stage 8: Fetch Current Standings 📈

**Script:** `pipeline/scripts/fetch_standings.py`  
**Purpose:** Fetch and format current league standings  
**Dependencies:** Stage 0 (week detection)  
**Output:** 
- `pipeline/standings_data.json` (archive)
- `dashboard/frontend/public/api-standings.json` (dashboard)

**What it does:**
- Fetches roster data from Sleeper API
- Reads current week from Stage 0 config ⚠️
- Calculates standings metrics:
  - Win/loss/tie records
  - Points for/against
  - Division standings
  - Playoff positioning
- Writes to both pipeline and dashboard directories

**Critical Dependency:** Requires `current_week.json` from Stage 0

---

### Stage 9: Playoff Simulations 🎲

**Script:** `pipeline/scripts/simulate_playoff_scenarios.py`  
**Purpose:** Run Monte Carlo simulations for playoff probabilities  
**Dependencies:** Stage 0 (week detection), Stage 8 (standings)  
**Output:**
- `pipeline/playoff_scenarios_simulated.json` (archive)
- `dashboard/frontend/public/api-playoff-scenarios.json` (dashboard)

**What it does:**
- Reads current week from Stage 0 config ⚠️
- Fetches current standings
- Simulates remaining regular season games
- Projects final standings probabilities
- Calculates:
  - Playoff probability for each team
  - Division win probability
  - Bye week probability
  - Projected seeding
  - Clinch/elimination scenarios

**Simulation Details:**
- Runs 10,000+ simulations
- Uses team strength (points scored) to weight outcomes
- Accounts for remaining schedule
- Applies tiebreaker rules
- Identifies magic numbers

**Critical Dependencies:**
1. `current_week.json` from Stage 0 - determines remaining games
2. Current standings from Stage 8

**Why Week Matters:**
- Week 12 vs Week 13 = 4 more simulated games per team
- Incorrect week = wrong playoff probabilities
- Tuesday timing bugs would cause incorrect calculations

---

### Stage 10: Final Dashboard JSON Update 📦

**Script:** `pipeline/scripts/generate_dashboard_json.py`  
**Purpose:** Verify all dashboard JSON files are in place  
**Dependencies:** Stages 7, 8, 9  
**Output:** Verification that all files exist

**What it does:**
- Re-runs CSV → JSON conversion (Stage 7 repeat)
- Verifies standings JSON exists (from Stage 8)
- Verifies playoff JSON exists (from Stage 9)
- Ensures dashboard has complete data set

**Files Verified:**
- ✓ `api-trades.json`
- ✓ `api-teams.json`
- ✓ `api-stats-summary.json`
- ✓ `api-standings.json`
- ✓ `api-playoff-scenarios.json`

## Running the Pipeline

### Full Pipeline (Automated)

```bash
# From project root
python3 update_dashboard.py

# Runs all 10 stages in order:
# Stage 0: detect_current_week.py
# Stage 1: stage1_fetch_trades.py
# Stage 2: stage2_extract_assets.py
# Stage 3: stage3_cache_values.py
# Stage 4: stage4_final.py
# Stage 5: analyze_2026_pick_ownership.py
# Stage 6: generate_playoff_bracket.py
# Stage 7: generate_dashboard_json.py
# Stage 8: fetch_standings.py
# Stage 9: simulate_playoff_scenarios.py
# Stage 10: generate_dashboard_json.py (verify)
```

### Individual Stages

```bash
cd pipeline

# Stage 0: Always run first!
python3 scripts/detect_current_week.py

# Stage 1-6: Trade analysis
python3 stage1_fetch_trades.py
python3 stage2_extract_assets.py
python3 stage3_cache_values.py
python3 stage4_final.py

python3 scripts/generate_dashboard_json.py

python3 scripts/generate_dashboard_json.py
```

### Partial Pipeline (After Stage 0)

If you only need to update playoff data:

```bash
cd pipeline

# Stages 8-10 only (assumes Stage 0 already run)
python3 scripts/fetch_standings.py
python3 scripts/simulate_playoff_scenarios.py
python3 scripts/generate_dashboard_json.py
```

## Error Handling

### Stage 0 Fails

**Error:** Week detection fails (API error, network issue)

**Impact:** 🔴 **CRITICAL** - Pipeline cannot proceed

**Solution:**
```bash
# Retry Stage 0
cd pipeline
python3 scripts/detect_current_week.py

# If API is down, manually create config:
echo '{"current_week": 12, "last_updated": "Manual override"}' > config/current_week.json
```

---

### Stage 1-4 Fails

**Error:** Trade analysis fails

**Impact:** 🟡 **MODERATE** - Trades not updated, but standings/playoffs work

**Solution:**
```bash
# Re-run failed stage
cd pipeline
python3 stage1_fetch_trades.py  # Or whichever failed
```

---

### Stage 8 Fails

**Error:** Standings fetch fails

**Impact:** 🔴 **CRITICAL** - No standings data for Stage 9 simulations

**Solution:**
```bash
cd pipeline
python3 scripts/fetch_standings.py

# Verify output
ls -lh standings_data.json
cat ../dashboard/frontend/public/api-standings.json | jq '.teams | length'
```

---

### Stage 9 Fails

**Error:** Playoff simulations fail

**Impact:** 🔴 **HIGH** - No playoff probabilities on dashboard

**Common Causes:**
1. Missing `current_week.json` (Stage 0 not run)
2. Invalid week in config
3. Incomplete standings data

**Solution:**
```bash
# Check week config exists
cat pipeline/config/current_week.json

# Re-run Stage 0 if needed
cd pipeline
python3 scripts/detect_current_week.py

# Re-run Stage 9
python3 scripts/simulate_playoff_scenarios.py
```

## Performance Notes

### Stage Execution Times (Typical)

```
Stage 0: ~2-3 seconds    (API calls)
Stage 1: ~3-5 seconds    (API calls)
Stage 2: ~1 second       (parsing)
Stage 3: ~5-30 seconds   (KTC API, cached vs fresh)
Stage 4: ~2-3 seconds    (calculations)
Stage 5: ~1 second       (analysis)
Stage 6: ~2 seconds      (bracket generation)
Stage 7: ~1 second       (CSV→JSON)
Stage 8: ~2-3 seconds    (API calls)
Stage 9: ~10-30 seconds  (10K+ simulations)
Stage 10: ~1 second      (verification)

Total: ~30-80 seconds for full pipeline
```

### Optimization Opportunities

1. **Stage 3 Caching**: Dynasty values cached for 24 hours
2. **Stage 9 Parallelization**: Could run simulations in parallel
3. **Stage 7/10 Deduplication**: Currently runs twice (by design for verification)

## Summary

The 10-stage pipeline transforms raw Sleeper API data into a comprehensive fantasy football dashboard:

1. **Stage 0** validates current week (Tuesday-safe)
2. **Stages 1-4** analyze trades with dynasty values
3. **Stages 5-6** add pick tracking and playoff brackets
4. **Stages 7-10** generate dashboard JSON with standings and simulations

**Critical Success Factor:** Stage 0 must run first to provide validated week context for Stages 8-9. Without correct week detection, playoff simulations and probabilities will be incorrect.
