# Prototypes & Experimental Work

This document catalogs the prototype / experimental tracks explored via **MeshClaw** and
**claudekiro** sessions. None of this is wired into the running production dashboard under
`dashboard/frontend/` — it is exploratory analysis, alternative data sources, and
proof-of-concept UI. All of it lives on the `prototypes/experimental-work` branch.

**Layout on this branch**

| Path | What it holds |
|---|---|
| `prototypes/frontend-fc/` | FantasyCalc-backed fork of the dashboard frontend |
| `prototypes/data/ktc_history/` | KeepTradeCut historical value acquisition (scraper + built series) |
| `prototypes/data/ktc_comparison/` | Prod DB vs KTC value / trade-verdict / manager-ranking analysis |
| `prototypes/data/fc_comparison/` | Three-way DynastyProcess vs KTC vs FantasyCalc comparison |
| `prototypes/data/rb_vegas_bfb/` | RB "Vegas Bang-For-Buck" analysis |
| `prototypes/backups/` | `.bak` / `.ktc-backup` snapshots of prod files taken during experiments |
| `prototypes/CHANGELOG.md`, `prototypes/revert.sh` | Session log + revert script from the KTC acquisition work |
| `dashboard/frontend/src/**` (new waiver-wire files) | Dynasty waiver-wire metric components (see track 6) |

> **Note on `raw/`:** the 234 MB `data/ktc_history/raw/` HTML scrape cache (423 files) is a
> reproducible cache and is **intentionally excluded from git** (see the
> `prototypes/data/ktc_history/raw/` entry in `.gitignore`). It remains on the local disk and
> can be regenerated by re-running the fetch scripts. Only the built/processed outputs are committed.

## 1. FantasyCalc data source integration — `prototypes/frontend-fc/`

**What it is.** A full fork of the production dashboard frontend (Vite + React + TypeScript,
package name `trade-dashboard-frontend`) set up as a parallel app to explore driving the
dashboard off **FantasyCalc** revealed-preference values instead of the production value source.

**Data sources.** FantasyCalc current-values API (`/values/current`, Superflex / 2QB dynasty
PPR), plus the same static JSON contract as prod (`public/api-*.json`, `trades.json`,
`waiver-wire-page.json`, etc.). Includes `.env` toggles (`VITE_USE_LAMBDA_API`,
`VITE_API_BASE_URL`) mirroring the prod Lambda/static split.

**Status.** Experimental fork, runs independently. `node_modules` in the original tree was a
symlink to the prod frontend's `node_modules` and was dropped on archival; run `npm install`
in `prototypes/frontend-fc/` to build. `.env` is gitignored (contains only a public API
Gateway URL, also present in `.env.example`).

## 2. KTC historical value acquisition — `prototypes/data/ktc_history/`

**What it is.** A scraper + builder that acquires the full **KeepTradeCut** dynasty-value
*time series* for every player rostered across the owner's two Sleeper leagues, in both 1QB
and Superflex formats.

**Method (read-only).** KTC's per-player pages embed `playerSuperflex` / `playerOneQB` JS
objects with an `overallValue` array of `{d: "YYMMDD", v: value}` daily points. A single HTML
GET per player yields the complete history for both formats — no rendering or pixel
extraction needed. Player identity is resolved via Sleeper rosters joined to KTC slugs.

**Coverage (as of 2026-08-10).** 382 target players; 366 (95.8%) resolved to a KTC slug and
acquired; 16 unresolved (retired / not in KTC's ~500-player ranked universe). Date range
2020-04-01 → 2026-08-10; **908,777 rows** in `ktc_history.csv`.

**Key artifacts.** `fetch_ktc_history.py`, `fetch_ktc_pick_history.py`, `build_player_map.py`
(scripts); `ktc_history.csv` (50 MB, built series — kept), `ktc_pick_history.csv`,
`ktc_catalog.json`, `player_map.csv`, `manual_overrides.csv`, `_unresolved.json`,
`coverage_report.md`. The `raw/` scrape cache is excluded from git (see note above).

**Status.** Complete acquisition; feeds tracks 3 and 4.

## 3. KTC comparison / value sensitivity — `prototypes/data/ktc_comparison/`

**What it is.** A sensitivity study comparing the **production DB values** to **KTC** values
across the league's real trades: per-asset value deltas, recomputed trade verdicts, and
manager-ranking reshuffles.

**Headline findings.** The two systems agree strongly on ordering (current Spearman **0.96**)
but disagree enough on magnitude that **~32–43% of individual trade verdicts flip** and the
middle of the manager leaderboard reshuffles (8 of 13 managers reorder; biggest movers ±7/−8
ranks). Top and bottom of the standings are stable. Prod is comparatively bullish on aging
vets (Hill, Tua, Geno); KTC is comparatively bullish on younger upside/depth.

**Method.** Trade sides summed on the KTC scale; picks/FAAB (which KTC doesn't value) mapped
onto the KTC scale via a linear fit (`ktc ≈ 0.820·prod + 2336.5`). Superflex format.

**Key artifacts.** `build_comparison.py`, `recompute_impact.py`,
`build_ktc_dashboard_data.py` / `_v2.py` (scripts); `asset_value_comparison.csv` (+`_v2`),
`trade_verdicts_compare.csv`, `manager_rankings_compare.csv`; `comparison_report.md`,
`methodology_and_rank_comparison.md`. Has its own `CHANGELOG.md` / `revert.sh`.

**Status.** Analysis complete; explicitly a sensitivity study, not a claim that KTC is "correct."

## 4. Three-way value comparison (DP vs KTC vs FC) — `prototypes/data/fc_comparison/`

**What it is.** A scale-free rank comparison across three dynasty-value philosophies:
**DynastyProcess** (analyst ECR curve), **KeepTradeCut** (stated preference / crowd survey),
and **FantasyCalc** (revealed preference from ~1M real trades).

**Headline findings.** The two market sources agree with each other most (KTC–FC Spearman
**0.977**) and each correlates less with the analyst curve — *market ≈ market > market vs
analyst.* Market sources rank youth/upside higher; DP still rewards proven vets. Includes
per-position over/under-valuation, top-asset concentration / curve-shape analysis, and a
documented finding that **FantasyCalc exposes no history endpoint** (only a current snapshot +
`trend30Day` scalar), so an FC history series would require a custom daily scraper.

**Data sources.** DynastyProcess `values.csv` (`value_2qb`), the KTC history from track 2, and
the live FantasyCalc `/values/current` API. Superflex / 12-team / PPR; N=349 three-way
intersection.

**Key artifacts.** `build_three_way.py`, `build_fc_dashboard_data.py` (scripts);
`fc_values_current.json`, `three_way_rank_comparison.csv`/`.md`,
`position_and_pick_analysis.csv`, `valuation_insights.md`, `fc_ktc_research.md`.

**Status.** Analysis + methodology research complete.

## 5. RB Vegas Bang-For-Buck — `prototypes/data/rb_vegas_bfb/`

**What it is.** A single-file analysis (`rb_vegas_bfb.csv`, 34 RBs) that cross-references each
running back's **dynasty trade value** (KTC / DP / FC rank + value) against **projected
production** derived from Vegas season prop lines (rushing/receiving yards, TDs → PPR points),
then computes a per-source **bang-for-buck** ratio and ranking (`ktc_bfb`, `dp_bfb`, `fc_bfb`
plus their ranks and a `points_rank`).

**Purpose.** Surface RBs whose dynasty price is cheap or expensive relative to their expected
on-field production — i.e. where the market and projected output diverge most.

**Status.** Exploratory single-output dataset.

## 6. Dynasty waiver-wire metric components — `dashboard/frontend/src/**`

**What it is.** New waiver-wire analysis cards and a shared metrics util that extend the
production Waiver Wire page with dynasty-oriented metrics. These files are **new additions**
(not modifications of existing prod files) and are imported by the modified
`WaiverWireAnalysis.tsx`:

- `src/components/WaiverWire/DynastyValueAddedCard.tsx`
- `src/components/WaiverWire/BlueChipRateCard.tsx`
- `src/components/WaiverWire/ContestedWinRateCard.tsx`
- `src/utils/dynastyWaiverMetrics.ts` (`computeDynastyWaiverMetrics`)
- `src/pages/FaabMarket.tsx` — a standalone FAAB-market prototype page. Not routed by the
  active `App.tsx` (its route was intentionally removed from prod in a prior commit); it is
  referenced only by `App.tsx.bak`. Kept here as an orphan prototype.

**Modified tracked files (committed on this branch, not `main`).**
`src/pages/WaiverWireAnalysis.tsx` (wires in the three new cards + the metrics util),
`src/pages/Overview.tsx` (adds a `Flame` icon / FAAB touch-point), `src/types/waiver-wire.ts`
(+108 lines of dynasty-metric types), and the data files `public/api-teams.json` /
`public/nfl-top-100.json`.

**Status.** Prototype UI; committed to the experimental branch to keep it buildable, but
deliberately kept off `main`.
